# 用 AI 助手安装 SintBot 1.4.17

[English](../AI-ASSISTED-INSTALL.md) · 简体中文

使用实际运行 SintBot 的 Mac 本地终端；云端终端不能替用户的 Mac 安装。按[安装指南](./install.md)操作，本版支持 1–32 个飞书群、每群选用 Codex 或 Claude Code，以前台方式运行。

1. 核对 macOS、Node 22 及以上、Codex 或 Claude Code 的实际程序与登录、是否已有 SintBot 进程。不输出凭据，保留已有安装、配置和状态。
2. 运行指南中的一行安装命令；`--dry-run` 为可选预览。用户已经授权的步骤继续执行，只问缺失的决定。安装器不修改 Node、Codex、Claude Code、终端配置或服务。
3. 安装器会验证 `~/.local/share/sintbot/bin/sintbot` 的版本和核心加载。安装程序包成功不等于群测试成功。
4. 优先用 `sintbot connect` 接入：它打印扫码链接并打开本机二维码页面，扫码和手机确认只能由用户本人完成；之后它自己建项目目录、建群、写配置并初始化，密钥不需要经过助手。已有飞书配置或服务在跑时它会拒绝，不要删文件绕过。扫码走不通再按安装指南的手动路径准备配置：让用户在本地输入密钥，或使用已经授权的凭据引用，不显示秘密。复用授权飞书应用时，确认没有另一个进程连接该应用。
5. 手动路径下，只有全新状态才能执行 `init`（`connect` 已经初始化过的不要再执行），然后执行 `start --preflight`。若已有日志或未结收据而拒绝启动，不得删文件、新造日志权威或篡改收据来绕过。
6. 前台运行，用已经授权的账号在群内发只读请求，把回复和文件对照，再正常停止并验证重启。没有真人协助时可用授权测试账号发送，并记录实际发送方式，不称为独立真人验收；机器人自己发的接口消息可能被忽略，不能当作用户入站消息。
7. 本轮临时进程用完停止。说明安装了什么、实际验证了什么、还缺什么。本版不注册自动后台服务。

## 可复制的请求

```text
按一行安装指南，在这台 Mac 安装 SintBot 1.4.17。保留已有服务、配置、状态和 Codex 或 Claude Code 账号数据，不输出凭据。验证实际入口与二进制核心，配置飞书群及各群的执行器，只对全新状态初始化。运行前台预检和已授权的只读群测试，对照结果，再验证正常停止与重启。完成后停止临时进程，并区分程序包安装与群验收结果。
```
