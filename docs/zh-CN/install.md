# 安装 SintBot 1.4.19

[English](../install.md) · 简体中文

准备一台 Mac、Node.js 22 及以上，以及保存在本机的项目。执行器至少装好并登录一个：Codex，或 Claude Code。本版连接中国区飞书的 1–32 个群，每个群绑定一个本地项目，以前台方式运行。

## 桌面 App

Apple silicon Mac 可[下载 SintBot](https://github.com/sintlab/sintbot-desktop/releases/latest)，拖到「应用程序」后打开。App 自带 Node.js；选择项目和执行器后，可直接本机对话或扫码接入飞书。关窗口或退出 App 后服务继续运行；停止后跨登录保持停止，直到点击启动。「移除后台服务」保留配置与历史。

## 1. 一行安装

```bash
curl -fsSL https://sintbot.com/install.sh | bash
```

安装器会自动检查环境，把 `sintbot@1.4.19` 装到 `~/.local/share/sintbot`，并验证程序入口、内置核心和飞书模块。看到 `Installed and verified SintBot 1.4.19` 就可以继续。不需要 sudo。

可选预览：在命令末尾加 `-s -- --dry-run`。要自定义安装位置，设置 `SINTBOT_INSTALL_DIR` 环境变量，并同步修改后面的可执行文件路径。

## 2. 在浏览器里接入飞书（推荐）

前提：手机飞书当前处于企业/团队身份；没有组织的个人身份扫不了，需先新建一个团队（免费）。扫码创建的应用归扫码人所在的组织，审批与否取决于组织设置。

```bash
"$HOME/.local/share/sintbot/bin/sintbot" start --ui
```

还没有配置文件时，这条命令不会报错，而是在本机打开接入页（`http://127.0.0.1:4600`，只有这台 Mac 能访问）。页面上填项目名（默认 `sintbot`，会在 `~/Projects` 下新建并放一份 `README.md`）或选一个已有目录，两个执行器都装了就选一个，不是组织管理员就勾上精简接入，然后点「开始扫码」。用手机飞书扫页面上的二维码并确认。接下来它依次：取得应用凭证 → 自检 → 放开通讯录范围与可用范围并发布版本 → 创建群并把你拉进去 → 新建项目目录 → 写入 `~/.sbot/config.json` → 初始化消息日志，每一步的结果都显示在页面上。扫码一旦确认，应用就已在你的组织里创建；之后任一检查失败都会在建目录、写配置之前停下，页面给出「重试」（复用已创建的应用，不会再建一个）；自动建群失败时页面会让你手动建群、拉入机器人，粘贴群 ID 后点「继续」。

显示二维码前会读取所选执行器的实时型号清单，在页面显示推荐型号和思考深度，并明确保存到新群配置。清单暂时取不到时会在创建应用之前停下；检查执行器登录和网络后重试。接入后可在控制台或通过 `/model` 调整，已有群的选择不会被覆盖。

接入完成后服务直接接着启动，页面几秒后切到控制台。保持终端开启。在新群里发“读取项目 README 的第一行，只回复这一行”，并和项目目录里的 `README.md` 对照。

### 先不接飞书，在本机对话

没有企业/团队身份，或者只想先试试：接入页最下面有「先在本机用，不接聊天软件」。它不扫码、不创建任何应用，用页面上选的项目和执行器写好配置，服务随即启动并打开控制台的「对话」页。在那里直接说要做什么，本机的 Claude Code 或 Codex 在项目目录里处理，回答回到这一页。对话记录保存在数据目录的 `local-chats/` 下，只在这台 Mac 上。

本机对话与飞书群走同一套处理流程：消息有登记、任务结果不明时暂停等待确认而不是重做、`/help` 列出的命令同样可用。和群里不同的是：回答在一轮结束时一次显示（处理中页面显示计时和「停止」），暂不支持图片和文件，也没有群消息工具。

之后要接入飞书：先停止 SintBot，运行下面的命令并用手机飞书扫码确认，再照常启动。原有的本机对话、记录和设置都保留，命令会先在数据目录的 `config-backups/` 里备份配置；新群的消息日志在下次启动时自动登记。

```bash
"$HOME/.local/share/sintbot/bin/sintbot" connect --attach
```

### 终端方式

不想开浏览器也可以在终端做同一件事，参数对应页面上的选项：

```bash
"$HOME/.local/share/sintbot/bin/sintbot" connect
```

在交互终端里它会先问项目名（直接回车即用默认的 `sintbot`），然后打印扫码链接，并打开一个本机页面显示二维码；步骤与上面相同，结果打印在终端，失败时给出带 `--app-id` 的重跑命令。

- 凭证明文写在 `~/.sbot/config.json`（文件 0600、目录 0700）。要改回环境变量，把 `appId` / `appSecret` 改成 `"env:FEISHU_APP_ID"` / `"env:FEISHU_APP_SECRET"`，并在每次启动前导出这两个变量。
- `--basic`：公司组织里的非管理员使用。不申请 `application:application:patch`，跳过放开范围与发布；之后请管理员在开放平台补这两步。
- `--app-id cli_…`：复用已有应用（给它追加权限，不新建），用于中途停下后重跑或审核通过后继续。只在没有配置文件、或配置文件属于这个应用且还没绑定任何群时允许；已绑定群的配置不会被替换。
- `--chat oc_…`：不自动建群，直接绑定你手动建好并拉入机器人的群（建群失败时的提示里会给出这条命令）。
- `--workdir /绝对路径`：绑定一个已存在的目录，不新建；`--name` 换默认目录名；`--provider codex|claude` 指定执行器（本机只装了一个时自动选）；`--no-open` 只打印链接、不打开页面。
- 已有飞书配置或服务正在运行时，`connect` 会拒绝执行。扫码会申请模型卡所需的卡片回调。`/model` 点选卡没有反应时，按第 4 节检查回调订阅。

## 3. 日常启动

接入完成后以后每次启动都用同一条命令；配置在默认位置时和接入时那条一样：

```bash
"$HOME/.local/share/sintbot/bin/sintbot" start --ui
```

它会预检配置和执行器、连接飞书并打开本机控制台。保持终端开启。用了 `--config` 或 `--data-dir` 的，启动时带同样的参数。预检通过不代表飞书认证或消息送达已经验证。

## 4. 手动接入（备选）

扫码失败、管理员不放行，或者想自己管理应用时，走下面的手动路径；内容与之前的安装步骤相同。

<details>
<summary>展开手动步骤</summary>

#### 4.1 创建应用

在 [飞书开放平台](https://open.feishu.cn/) 创建企业自建应用，启用机器人，在「权限管理」开通与扫码接入相同的权限：`im:message.group_msg`、`im:message:readonly`、`im:message:send_as_bot`、`im:resource`、`im:message.reactions:write_only`、`im:chat`、`cardkit:card:write`、`contact:contact.base:readonly`、`contact:department.base:readonly`、`contact:user.base:readonly`，并在「数据权限」把通讯录授权范围设为全部成员；事件订阅选择长连接并订阅消息接收；回调订阅同样选择长连接接收回调并订阅卡片回传交互（群里点选 `/model` 卡片要用）。发布应用后，把机器人加入要使用的群，取得每个群的 `oc_…` 群 ID。

在 macOS 默认终端中输入应用凭据（密钥输入时不显示）：

```zsh
read -r "FEISHU_APP_ID?Feishu App ID: "
read -rs "FEISHU_APP_SECRET?Feishu App Secret: "
printf '\n'
export FEISHU_APP_ID FEISHU_APP_SECRET
```

不要把密钥发进群或提交到仓库。后续步骤都在这个终端里做；新开终端时需要重新设置这两个变量。

#### 4.2 手写配置

用 `mkdir -p ~/.sbot && chmod 700 ~/.sbot` 创建私有配置目录，再创建 `~/.sbot/config.json`。把群 ID 和项目绝对路径换成你自己的，项目目录必须已经存在。下面的示例绑定两个群：一个用 Codex，一个用 Claude Code。只有一个群时删掉另一项即可。

```json
{
  "defaultProvider": "codex",
  "providers": {
    "codex": { "runner": "codex" },
    "claude": { "runner": "claude" }
  },
  "feishu": {
    "appId": "env:FEISHU_APP_ID",
    "appSecret": "env:FEISHU_APP_SECRET",
    "onlyWhenMentioned": false
  },
  "groups": {
    "oc_REPLACE_WITH_FIRST_CHAT_ID": {
      "platform": "feishu",
      "provider": "codex",
      "workdir": "/absolute/path/to/first/project",
      "permissionMode": "dontAsk",
      "steer": true
    },
    "oc_REPLACE_WITH_SECOND_CHAT_ID": {
      "platform": "feishu",
      "provider": "claude",
      "workdir": "/absolute/path/to/second/project",
      "permissionMode": "dontAsk"
    }
  }
}
```

保存后执行 `chmod 600 ~/.sbot/config.json`。

- `permissionMode: "dontAsk"` 是受限权限，适合先在测试群试用。确认需要让它修改文件、执行命令时，改为 `"bypassPermissions"`（完全访问）。
- 要固定 Claude 型号，可在 `providers.claude` 里加 `"model"`；不写就用这台机器上 Claude Code 的默认模型。
- 同时运行的任务默认最多 2 个，可在顶层加 `"agent": { "maxConcurrent": 4 }` 调整（1–32）。

#### 4.3 初始化并启动

在刚才的终端里一次复制执行（手动路径需要自己执行 `init`）：

```bash
SINTBOT="$HOME/.local/share/sintbot/bin/sintbot"
"$SINTBOT" init --config "$HOME/.sbot/config.json" &&
"$SINTBOT" start --config "$HOME/.sbot/config.json" --preflight &&
"$SINTBOT" start --config "$HOME/.sbot/config.json" --ui
```

这组命令依次初始化消息日志、预检配置和执行器、连接飞书并打开本机控制台，任一步失败就停止。**初始化只运行一次**；以后重启不要再执行 `init`。保持终端开启。

在群里发“读取项目 README 的第一行，只回复这一行”，并和本地文件对照。预检通过不代表飞书认证或消息送达已经验证。

## 5. 在群里使用

直接发文字就是给它派任务。回复以卡片呈现：模型开始输出时出现；25 秒还没有输出也会先出现。运行中卡片显示已跑多久、正在做什么和已完成的步骤，结束后这些步骤收进「过程」折叠区。

| 命令 | 作用 |
| --- | --- |
| `/status` | 本群状态：模型、项目、是否在忙（在忙时含步数和正在做什么）、排队数 |
| `/skip` | 只放弃当前任务，排队的接着处理，之前的对话保留 |
| `/stop` | 停止当前任务，连同排队的一起取消；之前的对话保留 |
| `/new` | 忘掉之前的对话，开始新的一段（只在本群空闲时生效） |
| `/model` | 打开点选卡，选后端、型号和思考深度后点「确认更新」；也可直接发 `/model high`、`/model 型号`、`/model 后端`。换型号或调深度接着当前对话，换后端开始新的一段对话；只在本群空闲时生效 |
| `/hud` | 当前模型的额度与本段对话的用量；Claude 群还显示空闲整理线和上次整理时间 |
| `/issue 一句话` | 记下问题反馈，在控制台概览里查看和标记处理 |
| `/help` | 查看可用命令，以及本群的项目和模型 |

命令单独发一条；除 `/issue` 和 `/model` 外，后面不要跟别的字。如果飞书应用还订阅了消息撤回事件（扫码接入会自动订阅，手动接入建议一并订阅），撤回自己发的消息即取消那件事：还在排队的直接丢弃；当前任务只由这一条触发时会停下；两种执行器中，撤回已交给执行器的补话均会取消整轮，包括已受理但尚未读取的补话。

Codex 和 Claude Code 的忙时跟进默认开启；`steer:false` 改为排队，显式 `steer` 优先于旧 Codex 开关。Claude Code 未提供所需输入能力时保留排队。长工具调用可能延迟读取；确认读取后回复卡才跟随补话，续轮答案合并为一条最终回复。某一轮模型报错或没有结果时，只在本群提示重新发送，不会自动重试。某个群上一轮的结果无法确认时（例如回复是否送达不明），只暂停这个群，它收到新消息会回一句说明，其他群照常；不重放、不重试。

回复卡移到已确认读取的补话下方时，会立即保留已有文字，后续输出继续更新；移动卡片不会重新启动任务。

走 Claude Code 的群会在一轮结束、群里没人等的时候整理会话：上下文到了模型卡「压缩」阈值的一半，就对同一会话跑一次 `/compact`，群里不发消息，新消息到来会先停掉整理再开始这一轮。整理占一个并发名额，只在还有空余名额时进行；阈值为 0 时不整理。Claude 订阅额度改从每轮自带的额度事件读取，额度接口最多半小时查一次。

## 6. 控制台

型号与思考深度按群选：在「群 · 项目」卡的「模型」行选后端和型号，下一行选深度，清单取自本机 Codex / Claude Code 的实时数据；订阅登录的模型卡上不再设型号和深度，第三方端点的型号仍在模型卡上设置。升级后，模型卡上原有的型号和深度会自动写进各群，生效值不变、会话不重置，改前备份配置。模型卡区分设置值与运行回报，容量依据可在「容量与运行信息」中查看。Codex 上下文窗口和各模型自动压缩都只提供「执行器默认 / 自定义」，仅自定义时显示数值输入；从下轮生效，保留当前会话。Codex 自定义窗口不能超过已知目录上限。压缩值对 Codex 表示阈值，对 Claude Code 表示窗口，实际可能提前触发。旧配置中的全局压缩值会转换为原有各模型的独立值，已有逐模型设置优先；新模型默认交给执行器，不继续继承旧全局值。读取不改磁盘，下一次正常保存配置时写入转换结果。

概览合并群项目与并发信息，每行显示执行器、状态与耗时、项目目录、模型和配置的思考深度、最近上报的上下文用量。选择群后查看对应任务，展开任务查看工具、回复和用量。上下文是当前会话采样，不是累计消耗；容量未知或历史采样会明确标注。群行图标按当前状态提供插话、停止与新会话操作。

带 `--ui` 启动后，在本机浏览器打开 `http://127.0.0.1:4600`。控制台可以查看各群状态、停止任务、给空闲的群开新会话、绑定新群、给空闲的群切换模型或项目目录、添加和设置模型。要从局域网访问，先在控制台的设置里设访问密码，再开启局域网访问。

「对话」页列出本机对话，可以新建（选项目目录和模型）、发消息、停止当前任务、开新会话；模型、权限和项目目录仍在「群 · 项目」里改，本机对话在那里和群并列。只有本机对话、还没接聊天平台时，控制台打开后先显示这一页。

群忙时也可以使用控制台「插话」：按本群跟进设置，等待模型读取或进入队列。「已受理」不代表模型已经读取。新会话与模型切换仍需等待群空闲。

「设置 → 软件更新」会检查新版本。按上面前台方式运行时，卡片给出升级步骤：按 Ctrl-C 等待退出，重新运行一行安装命令，再用原来的命令启动。如果用你自己的 launchd 后台任务启动 SintBot，「现在升级」会等所有群空闲、记录结清后，把新版本装到独立的发行目录并切换过去；新版本 90 秒内没连上全部群会自动换回旧版。升级时窗口逐步显示进度，服务重启时页面自动重连，也可以放到后台继续。升级后首次启动会在每个在服务的群发一张版本公告卡，列出这一版的更新；不想播报就在「设置 → 软件更新」取消「升级后向群里播报」。

不用控制台也能加群：在配置里加上新群，停止后重新 `start` 即可，新群会自动登记。已绑定的群不能通过改配置删除或改名。

升级安装失败后可重新尝试：重试使用新目录，保留失败产物供排查，校验成功后才切换。

## 停止与重启

按 Ctrl-C 并等待退出。配置里用的是 `env:` 引用时，先确认环境变量已设置，再执行：

```bash
"$HOME/.local/share/sintbot/bin/sintbot" start --config "$HOME/.sbot/config.json" --ui
```

某个群一直暂停时，先重启：记录能恢复的群会自己重新开放，并提示一次重新发送。重启后仍暂停，先核对这个群实际发生了什么，再停止服务，封存这个群的事故记录：

```bash
"$HOME/.local/share/sintbot/bin/sintbot" incident seal --config "$HOME/.sbot/config.json" --group oc_暂停的群ID
```

封存会把原日志原样留在数据目录的 `incidents/` 下，并给这个群换一份新日志；封存前没处理完的消息不会再处理。再次启动服务，这个群就重新开放。有群会保持暂停时，预检会失败。不要通过删除日志或重复发送来绕过暂停。一个飞书应用同一时间只运行一个连接进程。本版不自动注册后台服务。
