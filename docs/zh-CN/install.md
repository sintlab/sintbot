# 安装 SintBot 1.4.30

[English](../install.md) · 简体中文

准备一台 Mac、Node.js 22 及以上，以及保存在本机的项目。执行器至少装好并登录一个：Codex，或 Claude Code。本版支持共 1–32 个项目对话，可接 Slack、中国区飞书群和企业微信单聊或群，每个对话绑定一个本地项目，以前台方式运行。

## 桌面 App

Apple silicon Mac 可[下载 SintBot](https://github.com/sintlab/sintbot-desktop/releases/latest)，拖到「应用程序」后打开。App 自带 Node.js；选择项目和执行器后，可接入 Slack、扫码接入飞书、扫码创建企业微信机器人，或直接本机对话。关窗口或退出 App 后服务继续运行；停止后跨登录保持停止，直到点击启动。「移除后台服务」保留配置与历史。

企业微信请查看独立的[接入与使用指南](./platforms/wecom.md)，Slack 请查看 [Slack 接入与使用指南](./platforms/slack.md)。

## 1. 一行安装

```bash
curl -fsSL https://sintbot.com/install.sh | bash
```

安装器会自动检查环境，把 `sintbot@1.4.30` 装到 `~/.local/share/sintbot`，并验证程序入口、内置核心和飞书模块。看到 `Installed and verified SintBot 1.4.30` 就可以继续。不需要 sudo。

可选预览：在命令末尾加 `-s -- --dry-run`。要自定义安装位置，设置 `SINTBOT_INSTALL_DIR` 环境变量，并同步修改后面的可执行文件路径。

## 2. 在浏览器里接入（推荐）

```bash
"$HOME/.local/share/sintbot/bin/sintbot" start --ui
```

还没有配置文件时，这条命令不会报错，而是在本机打开接入页（`http://127.0.0.1:4600`，只有这台 Mac 能访问）。选好项目和执行器，再选聊天平台。

### 飞书

前提：手机飞书当前处于企业/团队身份；没有组织的个人身份扫不了，需先新建一个团队（免费）。扫码创建的应用归扫码人所在的组织，审批与否取决于组织设置。

在接入页的「聊天平台」里选**飞书**。页面上填项目名（默认 `sintbot`，会在 `~/Projects` 下新建并放一份 `README.md`）或选一个已有目录，两个执行器都装了就选一个，不是组织管理员就勾上精简接入，然后点「开始扫码」。用手机飞书扫页面上的二维码并确认。接下来它依次：取得应用凭证 → 自检 → 放开通讯录范围与可用范围并发布版本 → 创建群并把你拉进去 → 新建项目目录 → 写入 `~/.sbot/config.json` → 初始化消息日志，每一步的结果都显示在页面上。扫码一旦确认，应用就已在你的组织里创建；之后任一检查失败都会在建目录、写配置之前停下，页面给出「重试」（复用已创建的应用，不会再建一个）；自动建群失败时页面会让你手动建群、拉入机器人，粘贴群 ID 后点「继续」。

显示二维码前会读取所选执行器的实时型号清单，在页面显示推荐型号和思考深度，并明确保存到新群配置。清单暂时取不到时会在创建应用之前停下；检查执行器登录和网络后重试。接入后可在控制台或通过 `/model` 调整，已有群的选择不会被覆盖。

接入完成后服务直接接着启动，页面几秒后切到控制台。保持终端开启。在新群里发“读取项目 README 的第一行，只回复这一行”，并和项目目录里的 `README.md` 对照。

### Slack

Slack 没有扫码建应用这一步，所以在页面上分三小步完成，不用开终端：

1. 点「在 Slack 创建应用」。Slack 打开时应用的权限和事件已经填好；选择工作区，点 **Next**，再点 **Create**。
2. 在应用的 **Basic Information** 页生成一枚带 `connections:write` 权限的应用级令牌并粘贴（`xapp-` 开头）。页面会立即验证。
3. 点「打开安装页」，把应用安装到工作区，再粘贴 **Bot User OAuth Token**（`xoxb-` 开头）。

点「连接 Slack」，然后在 Slack 里给机器人发任意一句话：私聊，或在已经邀请它的频道里 @它。这个会话就绑定到项目，服务随即启动。

你需要有在工作区安装应用的权限；自己新建的免费工作区也可以。两枚令牌明文保存在 `~/.sbot/config.json`（文件 0600、目录 0700）。Slack 里命令以 `!` 开头（`!status`、`!stop`、`!new`），因为 `/` 被 Slack 自己占用。完整步骤、日常用法和排查见 [Slack 指南](./platforms/slack.md)。

已经在用的安装要加 Slack：打开控制台「设置 → Slack」，现有连接、项目和历史都保留。

### 先不接聊天平台，在本机对话

没有企业/团队身份，或者只想先试试：接入页最下面有「先在本机使用」。它不扫码、不创建任何应用，用页面上选的项目和执行器写好配置，服务随即启动并打开控制台的「对话」页。在那里直接说要做什么，本机的 Claude Code 或 Codex 在项目目录里处理，回答回到这一页。对话记录保存在数据目录的 `local-chats/` 下，只在这台 Mac 上。

本机对话与飞书群走同一套处理流程：消息有登记、任务结果不明时暂停等待确认而不是重做、`/help` 列出的命令同样可用。和群里不同的是：回答在一轮结束时一次显示（处理中页面显示计时和「停止」），暂不支持图片和文件，也没有群消息工具。

之后要接 Slack 或企业微信，在控制台「设置」里添加（见下文「接入 Slack」「接入企业微信」）。之后要接入飞书：先停止 SintBot，运行下面的命令并用手机飞书扫码确认，再照常启动。原有的本机对话、记录和设置都保留，命令会先在数据目录的 `config-backups/` 里备份配置；新群的消息日志在下次启动时自动登记。

```bash
"$HOME/.local/share/sintbot/bin/sintbot" connect --attach
```

### 终端方式

不想开浏览器也可以在终端做同一件事，参数对应页面上的选项：

```bash
"$HOME/.local/share/sintbot/bin/sintbot" connect
```

在交互终端里它会先问项目名（直接回车即用默认的 `sintbot`），然后打印扫码链接，并打开一个本机页面显示二维码；步骤与上面相同，结果打印在终端，失败时给出带 `--app-id` 的重跑命令。

- 凭证明文写在 `~/.sbot/config.json`（文件 0600、目录 0700）。要改回环境变量，把 `appId` / `appSecret` 改成 `"env:FEISHU_APP_ID"` / `"env:FEISHU_APP_SECRET"`，并在每次启动前导出这两个变量。
- `--basic`：公司组织里的非管理员使用。不申请 `application:application:patch`，跳过放开范围与发布；之后请管理员在开放平台补这两步。
- `--app-id cli_…`：复用已有应用（给它追加权限，不新建），用于中途停下后重跑或审核通过后继续。只在没有配置文件、或配置文件属于这个应用且还没绑定任何群时允许；已绑定群的配置不会被替换。
- `--chat oc_…`：不自动建群，直接绑定你手动建好并拉入机器人的群（建群失败时的提示里会给出这条命令）。
- `--workdir /绝对路径`：绑定一个已存在的目录，不新建；`--name` 换默认目录名；`--provider codex|claude` 指定执行器（本机只装了一个时自动选）；`--no-open` 只打印链接、不打开页面。
- 已有飞书配置或服务正在运行时，`connect` 会拒绝执行。扫码会申请模型卡所需的卡片回调。`/model` 点选卡没有反应时，按第 4 节检查回调订阅。

## 3. 日常启动

接入完成后以后每次启动都用同一条命令；配置在默认位置时和接入时那条一样：

```bash
"$HOME/.local/share/sintbot/bin/sintbot" start --ui
```

它会预检配置和执行器、连接配置里的聊天平台（Slack、飞书、企业微信）并打开本机控制台。保持终端开启。用了 `--config` 或 `--data-dir` 的，启动时带同样的参数。预检通过不代表聊天平台的认证或消息送达已经验证。

## 4. 手动接入（备选）

扫码失败、管理员不放行，或者想自己管理应用时，走下面的手动路径；内容与之前的安装步骤相同。

<details>
<summary>展开手动步骤</summary>

#### 4.1 创建应用

在 [飞书开放平台](https://open.feishu.cn/) 创建企业自建应用，启用机器人，在「权限管理」开通与扫码接入相同的权限：`im:message.group_msg`、`im:message:readonly`、`im:message:send_as_bot`、`im:resource`、`im:message.reactions:write_only`、`im:chat`、`cardkit:card:write`、`contact:contact.base:readonly`、`contact:department.base:readonly`、`contact:user.base:readonly`，并在「数据权限」把通讯录授权范围设为全部成员；事件订阅选择长连接并订阅消息接收；回调订阅同样选择长连接接收回调并订阅卡片回传交互（群里点选 `/model` 卡片要用）。发布应用后，把机器人加入要使用的群，取得每个群的 `oc_…` 群 ID。

在 macOS 默认终端中输入应用凭据（密钥输入时不显示）：

```zsh
read -r "FEISHU_APP_ID?Feishu App ID: "
read -rs "FEISHU_APP_SECRET?Feishu App Secret: "
printf '\n'
export FEISHU_APP_ID FEISHU_APP_SECRET
```

不要把密钥发进群或提交到仓库。后续步骤都在这个终端里做；新开终端时需要重新设置这两个变量。

#### 4.2 手写配置

用 `mkdir -p ~/.sbot && chmod 700 ~/.sbot` 创建私有配置目录，再创建 `~/.sbot/config.json`。把群 ID 和项目绝对路径换成你自己的，项目目录必须已经存在。下面的示例绑定两个群：一个用 Codex，一个用 Claude Code。只有一个群时删掉另一项即可。

```json
{
  "defaultProvider": "codex",
  "providers": {
    "codex": { "runner": "codex" },
    "claude": { "runner": "claude" }
  },
  "feishu": {
    "appId": "env:FEISHU_APP_ID",
    "appSecret": "env:FEISHU_APP_SECRET",
    "onlyWhenMentioned": false
  },
  "groups": {
    "oc_REPLACE_WITH_FIRST_CHAT_ID": {
      "platform": "feishu",
      "provider": "codex",
      "workdir": "/absolute/path/to/first/project",
      "permissionMode": "dontAsk",
      "steer": true
    },
    "oc_REPLACE_WITH_SECOND_CHAT_ID": {
      "platform": "feishu",
      "provider": "claude",
      "workdir": "/absolute/path/to/second/project",
      "permissionMode": "dontAsk"
    }
  }
}
```

保存后执行 `chmod 600 ~/.sbot/config.json`。

- `permissionMode: "dontAsk"` 是受限权限，适合先在测试群试用。确认需要让它修改文件、执行命令时，改为 `"bypassPermissions"`（完全访问）。
- 要固定 Claude 型号，可在 `providers.claude` 里加 `"model"`；不写就用这台机器上 Claude Code 的默认模型。
- 同时运行的任务默认最多 2 个，可在顶层加 `"agent": { "maxConcurrent": 4 }` 调整（1–32）。服务运行中这个值改不了，在控制台里也一样：改完配置文件后重启服务。

#### 4.3 初始化并启动

在刚才的终端里一次复制执行（手动路径需要自己执行 `init`）：

```bash
SINTBOT="$HOME/.local/share/sintbot/bin/sintbot"
"$SINTBOT" init --config "$HOME/.sbot/config.json" &&
"$SINTBOT" start --config "$HOME/.sbot/config.json" --preflight &&
"$SINTBOT" start --config "$HOME/.sbot/config.json" --ui
```

这组命令依次初始化消息日志、预检配置和执行器、连接飞书并打开本机控制台，任一步失败就停止。**初始化只运行一次**；以后重启不要再执行 `init`。保持终端开启。

在群里发“读取项目 README 的第一行，只回复这一行”，并和本地文件对照。预检通过不代表飞书认证或消息送达已经验证。

</details>

## 5. 在群里使用

在飞书群里，直接发文字就是给它派任务。回复以卡片呈现：模型开始输出时出现；25 秒还没有输出也会先出现。运行中卡片显示已跑多久、正在做什么和已完成的步骤，结束后这些步骤收进「过程」折叠区。

| 命令 | 作用 |
| --- | --- |
| `/status` | 本群状态：模型、项目、是否在忙（在忙时含步数和正在做什么）、排队数 |
| `/skip` | 只放弃当前任务，排队的接着处理，之前的对话保留 |
| `/stop` | 停止当前任务，连同排队的一起取消；之前的对话保留 |
| `/new` | 忘掉之前的对话，开始新的一段（只在本群空闲时生效） |
| `/model` | 打开点选卡，选后端、型号和思考深度后点「确认更新」；也可直接发 `/model high`、`/model 型号`、`/model 后端`。换型号或调深度接着当前对话，换后端开始新的一段对话；只在本群空闲时生效 |
| `/hud` | 当前模型的额度与本段对话的用量；Claude 群还显示空闲整理线和上次整理时间 |
| `/issue 一句话` | 记下问题反馈，在控制台概览里查看和标记处理 |
| `/help` | 查看可用命令，以及本群的项目和模型 |

命令单独发一条；除 `/issue` 和 `/model` 外，后面不要跟别的字。如果飞书应用还订阅了消息撤回事件（扫码接入会自动订阅，手动接入建议一并订阅），撤回自己发的消息即取消那件事：还在排队的直接丢弃；当前任务只由这一条触发时会停下；两种执行器中，撤回已交给执行器的补话均会取消整轮，包括已受理但尚未读取的补话。

在 Slack 里，命令以 `!` 开头而不是 `/`：`!status`、`!stop`、`!skip`、`!new`、`!model`、`!help`；在频道里要 @ 机器人再写命令。任务进行中你的消息上显示 ⏳（不用卡片），回答到达后变成 ✅；详见 [Slack 接入说明](./platforms/slack.md)的「日常使用」。在企业微信群里，每条任务和命令都要 @ 机器人；详见[企业微信接入说明](./platforms/wecom.md)。

Codex 和 Claude Code 的忙时跟进默认开启；`steer:false` 改为排队，显式 `steer` 优先于旧 Codex 开关。Claude Code 未提供所需输入能力时保留排队。长工具调用可能延迟读取；确认读取后回复卡才跟随补话，续轮答案合并为一条最终回复。某一轮模型报错或没有结果时，只在本群提示重新发送，不会自动重试。某个群上一轮的结果无法确认时（例如回复是否送达不明），只暂停这个群，它收到新消息会回一句说明，其他群照常；不重放、不重试。Claude Code，或关掉忙时跟进的 Codex 群，还没开始处理就明确报错（如额度用完）时，不暂停群：这条消息按没有处理收尾，群里说明原因；开着忙时跟进的 Codex 群这一版仍按原来的方式处理。服务因意外错误退出时打断的单条任务，重启后在原会话告知一次，不会重做，也不暂停群。

回复卡移到已确认读取的补话下方时，会立即保留已有文字，后续输出继续更新；移动卡片不会重新启动任务。

在声明支持 compact 的 Claude Code 版本上，空闲的群会在一轮正常结束后整理会话：上下文到了所设压缩窗口的一半，就对同一会话跑一次 `/compact`，群里不发消息。新消息到来会先停掉整理。整理占一个并发名额，只在还有空余名额时进行。压缩值为 0 时，常规压缩交给执行器，也不做这种空闲整理。整理成功后的下一轮，上一轮已经发进群里的回复会原样交还给模型（过长时只留结尾），这样紧接着按编号回复（比如「1 和 3」）也接得上；这段回复只留在内存里，服务重启后不再交还。Claude 订阅额度从每轮自带的额度事件读取：新事件一到，用量立即更新；事件还新鲜时，额度接口最多半小时补查一次。空闲整理在本版仍是实验性功能：压缩成功后的效果和缓存表现还有待真实模型验证。

## 6. 控制台

型号与思考深度按群选：在「群 · 项目」卡的「模型」行选后端和型号，下一行选深度，清单取自本机 Codex / Claude Code 的实时数据。每个群对用过的每个后端各记一份型号和深度，切回原后端时沿用原来的选择；换型号或调深度接着当前对话，只有换后端才开始新的一段对话。订阅登录的模型卡上不再设型号和深度。用 API Key 的预设模型卡也由各群自己选型号：清单是这家服务商的型号，卡上的 Key 可用后改为实时读取；没选过的群用卡上存的型号。自定义端点的型号仍在模型卡上设置，各群共用。升级后，模型卡上原有的型号和深度会自动写进各群，生效值不变、会话不重置，改前备份配置。模型卡区分设置值与运行回报，容量依据可在「容量与运行信息」中查看。Codex 上下文窗口和各模型自动压缩都只提供「执行器默认 / 自定义」，仅自定义时显示数值输入；从下轮生效，保留当前会话。Codex 自定义窗口不能超过已知目录上限。压缩值对 Codex 表示阈值，对 Claude Code 表示窗口，实际可能提前触发。旧配置中的全局压缩值会转换为原有各模型的独立值，已有逐模型设置优先；新模型默认交给执行器，不继续继承旧全局值。读取不改磁盘，下一次正常保存配置时写入转换结果。

在模型卡面板里点「检测登录」或「验证登录」，确认已登录后会重新读取可选型号，并显示新增和不再提供的型号；群里发 `/model` 时也会先取最新清单。Codex 的模型卡面板还会显示这台机器上 Codex 程序的版本，有新版时可以点「升级」：确认后重新全局安装最新版，各群从下一轮起使用；有群正在用 Codex 处理任务时不会升级，也只有通过 npm 全局安装的 Codex 才提供这个按钮；模型卡在配置里另外指定了 Codex 程序（`bin`）时，只显示那个程序的版本，需要在机器上手动升级。升级没成功时，原因留在这一行下面，按钮会回来，可以再试。Claude 订阅的模型卡对 Claude Code 程序也一样：npm 装的用 npm 重装，官方安装器装的用它自带的更新，其他方式装的需要在机器上手动升级；有群正在用 Claude Code 处理任务或排队时不会升级。

概览合并群项目与并发信息，每行显示执行器、状态与耗时、项目目录、模型和配置的思考深度、最近上报的上下文用量。选择群后查看对应任务，展开任务查看工具、回复和用量。上下文是当前会话采样，不是累计消耗；容量未知或历史采样会明确标注。群行图标按当前状态提供插话、停止与新会话操作。

带 `--ui` 启动后，在本机浏览器打开 `http://127.0.0.1:4600`。控制台可以查看各群状态、停止任务、给空闲的群开新会话、绑定新群、给空闲的群切换模型或项目目录、添加和设置模型。要从局域网访问，先在控制台的设置里设访问密码，再开启局域网访问。

「对话」页列出本机对话，可以新建（选项目目录和模型）、发消息、停止当前任务、开新会话；模型、权限和项目目录仍在「群 · 项目」里改，本机对话在那里和群并列。只有本机对话、还没接聊天平台时，控制台打开后先显示这一页。

群忙时也可以使用控制台「插话」：按本群跟进设置，等待模型读取或进入队列。「已受理」不代表模型已经读取。新会话与模型切换仍需等待群空闲。

「设置 → 软件更新」会检查新版本。按上面前台方式运行时，卡片给出升级步骤：按 Ctrl-C 等待退出，重新运行一行安装命令，再用原来的命令启动。如果用你自己的 launchd 后台任务启动 SintBot，「现在升级」会等所有群空闲、记录结清后，把新版本装到独立的发行目录并切换过去；新版本 90 秒内没连上全部群会自动换回旧版。升级时窗口逐步显示进度，服务重启时页面自动重连，也可以放到后台继续。升级后首次启动会在每个在服务的群发一张版本公告卡，列出这一版的更新，并附官网上这一版的更新记录链接；不想播报就在「设置 → 软件更新」取消「升级后向群里播报」。

不用控制台也能加群：在配置里加上新群，停止后重新 `start` 即可，新群会自动登记。已绑定的群不能通过改配置删除或改名。

升级安装失败后可重新尝试：重试使用新目录，保留失败产物供排查，校验成功后才切换。

### 定时任务

每个会话可以有自己的定时任务，在控制台里管理。一个任务有名称、时间和类型，类型有三种：

- **交给模型。** 到点时，会话里先出现一行带「【定时】」标记的消息（英文会话是 `[Scheduled]`），写着任务名称和任务内容的开头；随后任务内容按会话里的一条普通消息处理：会话正忙就排队，回答出现在这行消息下面。这一轮不接收补话，按标准速度运行。
- **只发一句。** 到点把这句话发进会话，不做别的。
- **运行命令。** 到点在会话的项目目录里运行一条命令，不进入会话；它用的是服务自身的权限，不受会话权限档位限制。成功时不说话，失败或超过时限（默认 15 分钟，可按任务设置）时在会话里发一行提示。

时间可以写 5 段 cron 表达式、`@daily` 这类别名、「每天 09:00」这类简写，或一个只执行一次的日期时间（`YYYY-MM-DD HH:mm`）。时间按产品时区（配置里的 `timezone`，默认 Asia/Shanghai）理解，任务也可以单独指定时区。

- **同一次至多触发一次。** 每次到点都先写入运行记录，再发消息或启动命令，不会触发第二次。结果不明的发送或运行（例如正好赶上服务停止）显示为「结果未知」，不会重做。
- **错过的不补。** 到点时服务没在运行，或晚了两分钟以上才轮到，这一次显示为「错过」。会话已暂停或服务正在升级时，这一次跳过并如实显示；「交给模型」的任务在会话等待人工确认、或已有两条消息在排队时同样跳过。
- **时钟调整。** 时钟回拨时，重复出现的那个时间只触发一次；时钟拨快时，当天不存在的那个时间不触发。
- **数据在哪。** 任务和运行记录保存在数据目录的 `schedules/` 里，不写进配置文件。这些文件读不出来时，只有定时任务停用，其他功能照常，原因写在服务日志里。
- **上限。** 每个会话最多 20 个任务，名称最长 60 个字，内容最长 4000 个字。企业微信会话暂不支持定时任务。

## 停止与重启

按 Ctrl-C 并等待退出。配置里用的是 `env:` 引用时，先确认环境变量已设置，再执行：

```bash
"$HOME/.local/share/sintbot/bin/sintbot" start --config "$HOME/.sbot/config.json" --ui
```

某个群一直暂停时，先重启：记录能恢复的群会自己重新开放，并提示一次重新发送。重启后仍暂停，先核对这个群实际发生了什么，再停止服务，封存这个群的事故记录：

```bash
"$HOME/.local/share/sintbot/bin/sintbot" incident seal --config "$HOME/.sbot/config.json" --group oc_暂停的群ID
```

封存会把原日志原样留在数据目录的 `incidents/` 下，并给这个群换一份新日志；封存前没处理完的消息不会再处理。再次启动服务，这个群就重新开放。由后台服务运行时（例如桌面版），控制台概览页「需要处理」卡上的「封存并继续」做同样的封存，服务随后自动重启；其他群有任务时要等它们结束。所有群都暂停时服务照常启动，控制台可以打开。有群会保持暂停时，预检会失败。不要通过删除日志或重复发送来绕过暂停。一个飞书或 Slack 应用同一时间只运行一个连接进程。本版不自动注册后台服务。

服务每次启动、每次在线修改设置后，都会把当时的配置原样存一份到数据目录的 `config-history/` 下，保留最近 50 份，文件只有本人可读。查看存过哪些版本、各改了哪些设置（只列设置项，不显示值）：

```bash
"$HOME/.local/share/sintbot/bin/sintbot" config history
```

要换回某一版，先停止服务，再执行下面的命令（版本写上面列出的编号，或它开头的一段）。还原前会先把当前配置存一份，所以还原本身也能撤回；受影响的群要求记录已结清，后端或项目目录变了的群会开新会话。重新启动后生效。服务在运行时这个命令会拒绝执行。

```bash
"$HOME/.local/share/sintbot/bin/sintbot" config restore 版本编号 --config "$HOME/.sbot/config.json"
```
